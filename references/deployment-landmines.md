# Deployment Landmines — sort-arena-web

Stack: Vercel + Vite + React SPA, our own backend at `sort-bot-arena/server/` on Railway, the third-party `sort-bot-api` also on Railway.

## Our backend on Railway

- Service: `sort-bot-arena-server` in the `sort-bot-api` Railway project. Public URL: `https://sort-bot-arena-server-production.up.railway.app`.
- Build: `railway.json` at repo root points at `server/Dockerfile`. The Dockerfile builds with the workspace context (root has `pnpm-workspace.yaml`), runs `tsc -p tsconfig.build.json`, then `pnpm --filter ... deploy --prod /tmp/deploy` to materialize a self-contained production bundle. The run stage copies `dist/` from build + `node_modules` + `package.json` from the `pnpm deploy` output.
- **Watch out:** the original Dockerfile copied `server/node_modules` into the run stage, but pnpm workspaces use symlinks into `.pnpm`, so the run image had no real deps and Node exited silently. Always use `pnpm deploy` for production extraction.
- DB (production): persistent libSQL/Turso. Provisioned 2026-05-01 as `sort-bot-arena-server` under the `justpinero` Turso account. Connection string lives in Railway env as `DATABASE_URL=libsql://sort-bot-arena-server-justpinero.aws-us-east-1.turso.io` + `DATABASE_AUTH_TOKEN=<token>`. Free tier (9 GB / 1B reads / 25M writes per month) is 3-4 orders of magnitude over our usage. Tokens are long-lived; rotate quarterly via `~/.turso/turso db tokens create sort-bot-arena-server` and update Railway.
- DB (local dev): file-backed SQLite at `file:./local.db` per `server/.env.example`. The libsql client treats `file:` and `libsql:` URLs interchangeably.
- Migrations are tracked in `schema_migrations`; runMigrations() is idempotent. Phase 9 added 0006-0009 (style col on personas, recent_battles, recent_tournaments, uploaded_inputs).
- Required env: `SORT_BOT_API_URL`, `DATABASE_URL`, `SESSION_SECRET`, `LEONARDO_API_KEY`, `ANTHROPIC_API_KEY`, `ALLOWED_ORIGINS`. Railway provides `PORT`.
- CORS: `ALLOWED_ORIGINS=https://sort-bot-arena.vercel.app` exactly. The frontend sends `credentials: 'include'`, so `Access-Control-Allow-Credentials: true` matters and the origin can't be `*`.

## Cookie auth across origins

- Session cookie set as `HttpOnly; Secure; SameSite=Lax`. Both the frontend (Vercel `*.vercel.app`) and the server (Railway `*.up.railway.app`) must be HTTPS in production for `Secure` to allow the cookie.
- `SameSite=Lax` lets the browser attach the cookie on top-level navigations and same-site requests. `fetch()` from the SPA needs `credentials: 'include'` to forward it.
- If the cookie disappears in the network tab on a deployed build, double-check that Vercel and Railway both serve over HTTPS and that the `Secure` flag isn't being downgraded by a proxy.

## Vercel

### SPA rewrite is mandatory

Without it, deep-links (e.g., `/leaderboard`) return 404 because Vercel looks for a static `/leaderboard` file. `vercel.json`:

```json
"rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
```

This file is checked in. If you change framework presets in the dashboard, double-check the rewrite is still present.

### Env vars must be set in **all three** environments

Production, Preview, Development. Setting only Production means preview deployments boot with `VITE_API_BASE_URL` unset → app throws at load. Vercel's UI defaults to "Production" only — easy to miss.

### `VITE_*` vars are baked at build time

A change to an env var requires a redeploy. Don't expect runtime override. This is a Vite contract, not a Vercel one.

### CSP must allow the backend origin and font CDNs

Header pattern (set in `vercel.json` or via the Vercel dashboard once we know the prod backend URL):

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
  font-src 'self' https://fonts.gstatic.com data:;
  img-src 'self' data: https://api.sort-arena.dev https://*.leonardoai.com;
  connect-src 'self' https://api.sort-arena.dev wss://api.sort-arena.dev;
  frame-ancestors 'none';
```

`'unsafe-inline'` for styles is required by shadcn-style component variants and inline `<style>` blocks generated by libraries like Framer Motion. Tighten if/when we move to nonces.

`connect-src` MUST include `wss://` if the backend ever upgrades SSE → WebSocket; for now SSE rides over the same `https://` origin so a single entry suffices.

### Build output

`vercel.json`:

```json
"buildCommand": "pnpm build",
"outputDirectory": "dist",
"installCommand": "pnpm install --frozen-lockfile"
```

Vite's default output directory is `dist` — leave it. Don't override unless you have a reason.

## Vite

### `import.meta.env` is the env API

`process.env` does not exist in client code. Linting catches this; the build does not.

### Mode-specific env files

- `.env` — committed defaults (none for this project; we leave it absent).
- `.env.local` — local dev overrides. Gitignored.
- `.env.production` / `.env.preview` — environment-specific. Use sparingly; prefer Vercel env vars for prod/preview.

## SSE + load balancer

Vercel's frontend is static and has no function timeouts; the SPA's `EventSource` opens a long-lived HTTPS connection to the **backend's** host. That host's load balancer must:

- Allow long-lived connections (Railway: increase `RAILWAY_TIMEOUT` to ≥ 60min for SSE routes; Fly: ensure `idle_timeout` on the proxy is set; both default to ~60s and will kill connections silently).
- Disable response buffering on the SSE route (nginx/CDN-level `proxy_buffering off`).
- Allow `text/event-stream` content-type unmodified.

The frontend cannot fix backend timeouts. If SSE drops with no error in the browser console mid-fight, suspect the LB before the app.

## CSP gotchas with Framer Motion

Framer Motion injects inline styles. `style-src 'self' 'unsafe-inline'` accommodates that. If you tighten to `'unsafe-hashes'` + per-rule hashes, Framer Motion will break silently — animations stop firing.

## Vite build perf in Vercel

Vercel's default Node version may lag local. Pin via `engines.node` in `package.json` (we have `>=20.10.0 <21`). Mismatch causes:

- `pnpm install` failing on lockfile resolution.
- Build succeeding locally but failing on Vercel due to a missing top-level `await` in a dependency.

## Generic gotchas

- **Validate env at module load.** `src/api/client.ts` throws on missing `VITE_API_BASE_URL`. The alternative — failing at first network call — is much harder to debug.
- **Never `echo` env vars to logs.** Even non-secret ones, because pipelines that get exfiltrated leak everything. Use `printf` or skip logging entirely.
- **Git secrets check on staged files.** Hook in `.claude/hooks/pre-tool-use-secrets.sh` blocks accidental commits of values that look like API keys. Don't disable it.

## Branch protection on `main` (slice A4)

Configured in the GitHub repo Settings → Branches. Phase 10 locks the
`main` branch behind these required status checks:

- `validate / validate` — lint + format-check + frontend & server typecheck +
  frontend & server vitest with coverage thresholds + frontend & server
  build (the workflow at `.github/workflows/ci.yml`).
- `e2e-mocked / e2e-mocked` — `pnpm exec playwright test --project=mocked`
  (the legacy MSW-in-browser outage spec).
- `e2e-real-server / e2e-real-server` — `pnpm exec playwright test
  --project=real-server` (smoke + G2-G6 flows against the real Hono
  server + libsql + stubbed sort-bot-api).
- `contract-drift / contract-drift` — runs `server/tests/contract-drift.test.ts`
  against every endpoint listed in `src/api/queries.ts`. The phase 8
  contract-drift bug would have been caught here.

Additional rules:

- **Require linear history.** No merge commits — squash or rebase only.
- **Require pull requests.** No direct pushes to `main`.
- **Require branches to be up to date before merging.** Forces the PR
  author to rebase if `main` advanced since the PR opened.
- **Restrict force pushes.** Off for everyone, including admins.

Coverage thresholds (gated by CI through the new vitest configs):

- Frontend (`vitest.config.ts`): lines 80 / branches 75 / functions 80 / statements 80.
- Server (`server/vitest.config.ts`): same — lines 80 / branches 75 / functions 80 / statements 80.

Drop below + CI fails. The `coverage.exclude` carve-outs keep test files,
the entry point, generated types, and config files out of the denominator.

Husky hooks (slice A3) provide a fast pre-merge gate locally:

- `.husky/pre-commit` — runs `pnpm exec lint-staged` (eslint --fix +
  prettier --write on staged files).
- `.husky/pre-push` — runs `pnpm typecheck` (frontend + node configs).

The `prepare` npm lifecycle script wires husky on `pnpm install`.

## What a clean deploy looks like

1. `pnpm install --frozen-lockfile` succeeds.
2. `pnpm build` produces `dist/` with `dist/index.html` and `dist/assets/*`.
3. Vercel serves `dist/index.html` for `/` and rewrites `/(.*)` → `index.html`.
4. The deployed page boots, reads `VITE_API_BASE_URL`, fetches a guest user from the backend, and renders the layout shell.
5. CSP headers visible in Network → Response Headers; no console errors about blocked resources.

Anything else, debug back from the network tab.
